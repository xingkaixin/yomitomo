维护 Obsidian、Logseq 等双链笔记库时，一个常见问题是“输入过载”：把阅读器里成百上千条原始高亮直接同步进笔记库，结果库里堆满脱离上下文的零碎摘抄，时间一长既不想翻看，也很难整理。

把 Yomitomo 和 Obsidian 组合使用的核心思路很简单：**阅读现场留在 Yomitomo，筛选和整理后的成文再进入 Obsidian**。Yomitomo 负责保存原文、锚定批注、展开讨论和沉淀定稿，再通过内置的 Markdown 导出把结果带入你的双链知识库。

---

## Yomitomo 与 Obsidian 的协作链路

```text
[ 原文阅读层 · Yomitomo ]
网页文章 / EPUB、AZW3、MOBI 电子书 / PDF / 文本文档 / 微信读书同步笔记
      │
      ▼（本地阅读、划线、记录想法）
[ 讨论与整理层 · Yomitomo ]
原文锚点划线 + 原样保存的想法 + @阅读理解助手多轮讨论
      │
      ▼（对关键讨论点击「把这些想法沉淀下来」）
[ 单条沉淀与问答层 · Yomitomo ]
单条沉淀稿（配合右侧审阅助手与 Git-diff 预览） / 阅读记忆「问书库」带引用回答
      │
      ▼（导出 Markdown .md / 复制 Markdown）
[ 双链笔记层 · Obsidian / Logseq / Notion ]
建立 [[双链]]、标签与主题 MOC，形成长期个人笔记网络
```

---

## 三步建立协作流程

### 第一步：在阅读现场消化，不把未加工摘抄直接塞进笔记库

在 Yomitomo 中导入网页、电子书或 PDF 后，选中关键段落点击「划线」或按 `A` 记下第一反应，用自定义颜色区分重点与存疑处。遇到概念模糊或推导存疑的地方，就在对应划线的讨论区 `@` 阅读理解助手（如 `@周砚`、`@沈清源`、`@顾行简`）把问题聊清楚。

这个阶段的所有原文、高亮坐标和讨论记录都保存在本地 SQLite 中，不污染 Obsidian 仓库。

### 第二步：沉淀关键判断，或用「问书库」做跨材料综合

当某条划线的讨论已经得出有价值的结论，点击讨论窗口中的「把这些想法沉淀下来」打开沉淀窗口：

1. 点击「整理讨论」将讨论要点追加到编辑区（仅追加，不覆盖你已有文字）；
2. 用自己的话改写为清晰、独立的观点或分析框架；
3. 在右侧审阅面板选择审阅助手（如 **何明衡** 检查逻辑、**唐简** 压缩冗余表述），在 Git-diff 内联预览中逐条点击「保留」或「放弃」，最后发布。

如果需要把多篇文章或几本书的观点合在一起整理，可以打开「阅读记忆 > 问书库」，限定在某个合集或指定来源内提问，获得附带原文引用的综合回答。

### 第三步：用内置 Markdown 导出把整理结果带入 Obsidian

Yomitomo 内置**导出 Markdown（`.md`）**与**复制 Markdown**，按不同粒度支持以下四种场景：

- **整篇文档导出**：在阅读器工具栏导出或复制整篇文章/电子书/PDF 的划线、想法、讨论和已发布沉淀；
- **单条沉淀导出**：在沉淀窗口或「沉淀」列表中导出或复制单条沉淀稿，适合直接作为 Obsidian 的原子笔记；
- **微信读书按章导出**：在微信读书书籍页面的工具栏中，按章节导出或复制该书的划线与想法；
- **「问书库」带引用复制**：将跨材料问答的结果连同来源引用直接复制为 Markdown，粘贴进 Obsidian 作为主题综述草稿。

在 Obsidian 中粘贴或放入 `.md` 文件后，按自己的体系补充 `#标签` 和 `[[双向链接]]`。日后需要查证原文上下文时，回到 Yomitomo：在「阅读库」按标题、作者、来源或合集找回文档，在文档内按 `⌘F / Ctrl+F` 搜索正文，或在「沉淀」与「阅读记忆」中检索已保存的笔记。

## 两种接入方式的对比

| 维度                  | 原始高亮全量自动同步         | Yomitomo 精读整理 + 按需导出 Markdown            |
| --------------------- | ---------------------------- | ------------------------------------------------ |
| **Obsidian 笔记密度** | 大量零散原句，后期整理成本高 | 以单条沉淀、整篇整理或带引用问答为主，噪声少     |
| **上下文追溯**        | 往往丢失前后段落和当时追问   | 原文、锚点与完整讨论流长期保留在 Yomitomo 本地   |
| **流转方式**          | 自动单向/双向同步            | 手动按需导出 `.md` 或复制 Markdown，没有自动同步 |

## 适用对象与使用边界

### 适合的读者

- Obsidian、Logseq、Notion 等笔记软件用户，希望在入库前先在阅读器内完成理解和筛选；
- 希望把微信读书笔记、PDF 研报和网页长文统一整理后再导出为 Markdown 归档的读者；
- 定期基于阅读积累写专栏、报告或研究笔记的创作者。

### 暂不适合的情况

- **依赖全自动无感同步**：Yomitomo 目前不提供与 Obsidian / Logseq / Notion 的自动单向或双向同步插件；
- **只在外部笔记工具里直接编辑原文批注**：原文锚点与讨论记录仍留在 Yomitomo，外部编辑不会回写。

## 常见问题解答 (FAQ)

### Q1：导出或复制到 Obsidian 的 Markdown 包含哪些内容？

**答：** 整篇文档导出包含划线、想法、讨论和已发布沉淀；单条沉淀导出包含该条沉淀内容；微信读书支持按章节导出划线与想法；「问书库」支持带来源引用复制。原文位置锚点与 Yomitomo 内部交互状态仍保留在 Yomitomo 本地中。

### Q2：在 Obsidian 里修改了导出的 Markdown，会同步回 Yomitomo 吗？

**答：** 不会。Yomitomo 目前不支持与 Obsidian 或 Notion 的自动双向同步。建议把 Yomitomo 当作原文与原始思考的本地档案库，把 Obsidian 当作跨主题加工和写作空间。
