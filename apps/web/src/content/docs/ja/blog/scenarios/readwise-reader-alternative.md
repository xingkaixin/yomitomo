デジタル読書や「あとで読む」ツールの分野で、Readwise ReaderはRSS集約、マルチデバイス同期、外部ノートアプリへの自動転送に強みがあります。一方で、ローカルへのデータ保存、AIモデルの選択自由度、継続課金を抑えた運用を重視する読者のあいだでは、ローカルファーストのデスクトップ環境を選ぶ動きも広がっています。

YomitomoとReadwise Readerは同じ領域の単純な代替品ではなく、設計思想が異なります。**クラウド型のマルチデバイス「あとで読む」・転送ハブ**か、**ローカル中心の精読・対話・まとめワークベンチ**か、という違いです。

## 主要項目の比較

| 比較軸 | Yomitomo | Readwise Reader |
|---|---|---|
| **基本コンセプト** | ローカルファーストのAI伴読・まとめ（蒸留）ワークベンチ | クラウド型マルチデバイス「あとで読む」集約・ハイライト転送ハブ |
| **対応形式** | Web記事、電子書籍（EPUB・AZW3・MOBI）、PDF、テキスト・Markdown、WeRead同期ノート | Web記事、RSS、ニュースレター、EPUB、PDF、動画トランスクリプト等 |
| **保存とプライバシー** | 読書データは端末内のSQLiteとファイル領域に保存。リモートAI利用時のみ処理に必要な本文・対話を設定先へ直接送信（他に更新確認・オフ可能な匿名テレメトリ・`models.dev` 価格表取得あり） | クラウドアカウントを通じて複数端末間で同期 |
| **オフライン利用** | 取り込み済み資料の閲覧・ハイライト・考え・検索はローカルで動作。事前取得したローカルモデル（Ollama等）を割り当てればクラウドAPIなしでAI対話も可 | オフライン閲覧に対応。同期やクラウドAIには通信が必要 |
| **AI対話モデル** | 原文に結び付くスレッドで6名の読書パートナーと対話、まとめ画面で6名のレビュー担当アシスタントが点検 | Ghostreaderによる要約、Q&A、用語解説などのクイック支援 |
| **注釈・まとめ・記憶** | 原文固定ハイライト（色変更可）＋考え＋1論点ごとのまとめ（蒸留）＋読書メモリー（「ライブラリに質問」「読み直す」「関連を探す」） | カラーハイライト＋メモ＋外部ノートアプリへの自動同期 |
| **WeRead（微信読書）連携** | 公式 Skill API でノート付き書籍をローカル同期。章別閲覧・Markdown出力・内蔵ウェブ版に対応 | 公式の直接連携はなし |
| **エクスポート** | 内蔵の「Markdown (.md) をエクスポート」「Markdownをコピー」（自動同期は非対応） | Readwise経由でObsidian・Notion・Logseq等へ自動同期 |
| **料金モデル** | アプリは無料・オープンソース。外部AIのAPI利用料やローカルモデル実行環境は各自で用意 | 有料サブスクリプション。最新の料金は公式ページで確認 |

Readwiseの対応範囲と料金は、[公式製品ページ](https://readwise.io/read)と[料金ページ](https://readwise.io/pricing)を参照してください。

## 3つの本質的な違い

### 1. 「広く集めて流す」か、「絞って原文と向き合う」か
- **Readwise Reader**：RSS、ニュースレター、SNSスレッドを毎日チェックし、スマホやタブレットから素早くハイライトを集める用途に向いています。
- **Yomitomo**：デスクトップで論文・専門書・長文記事を腰を据えて読み、`A` で自分の考えを書き留めながら理解を深める設計です。

### 2. AIの役割：クイック要約か、原文固定の対話とレビューか
- **Readwise Reader (Ghostreader)**：記事の要点把握や素早いQ&Aに便利です。
- **Yomitomo**：読者の明示的な操作（`@`、`Q`、「アシスタントに頼む」）でのみAIが起動します。読解スレッドでは `@黒沢 蓮`（前提を問う批評者）や `@白川 澪`（概念の翻訳者）などと議論し、1つのハイライトから開くまとめウィンドウでは **藤堂 玲奈**（論理監査官）や **佐伯 証**（根拠の記録官）などのレビュー担当アシスタントに文章を点検してもらえます。

### 3. 外部ノートへの渡し方：自動転送か、整理後のMarkdown出力か
- **Readwise Reader**：ハイライトを自動でObsidianやNotionへ同期したい人に最適です。
- **Yomitomo**：自動同期は行いません。その代わり、読書の現場で考えと対話を「まとめ（蒸留）」に整えたうえで、内蔵の「Markdown (.md) をエクスポート」や「Markdownをコピー」から必要な分だけ外部ツールへ持ち出せます。

## どちらを選ぶべきか

### Yomitomo が適している方
- 学術論文（PDF）や専門書（EPUB・AZW3・MOBI）を精読し、前提や論証を丁寧に検討したい方
- 読書データを端末内に保存し、アカウント不要で管理したい方（機密資料を扱う場合はタスクごとのAI送信先を確認し、必要に応じてローカルモデルを利用）
- 自前のAPIキーや端末内のOllamaモデルを使い分けたい方
- WeReadのハイライトとメモをローカルへ同期して手元に残したい方

### Readwise Reader が適している方
- RSS、ニュースレター、SNSスレッドなど大量のWeb情報を毎日流し読みしたい方
- スマートフォン、タブレット、電子ペーパー端末の間でのリアルタイム同期が必須な方
- ハイライトを自動でノートアプリへ転送したい方

## よくある質問 (FAQ)

### Q1: Readwiseに蓄積した過去のハイライトをYomitomoへ移行できますか？
**回答:** Readwiseアカウントの直接接続やCSVハイライトのインポーターはありません。PDF・EPUB・AZW3・MOBIの原本やMarkdown・テキスト文書は取り込めますが、Readwise上の注釈位置や対話履歴が自動で復元されるわけではありません。

### Q2: Yomitomoのスマートフォン版アプリはありますか？
**回答:** ありません。YomitomoはmacOS・Windowsのデスクトップ環境での精読、対話、まとめ作成に特化しています。
