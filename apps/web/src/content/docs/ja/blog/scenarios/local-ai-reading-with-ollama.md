YomitomoはOpenAI互換の接続を通じて、同じ端末で動くOllamaモデルに読書の質問を送信できます。Base URLを `http://localhost:11434/v1` に設定し、取得済みのローカルモデルを読書タスクに割り当てます。

Yomitomoプロジェクトがv0.18.2の設定と [Ollama公式の互換API文書](https://docs.ollama.com/api/openai-compatibility)に基づいてまとめました。ハードウェアの実測レポートではありません。

## 1. ローカルモデルを用意する

[Ollama公式サイト](https://ollama.com/)からインストールし、オンラインでモデルを取得します。以下は設定例です。

```bash
ollama pull qwen2.5:7b
ollama run qwen2.5:7b
```

実行できるサイズや速度は、メモリ、量子化、コンテキスト長などによって変わります。先にOllamaで応答を確認してください。ローカル推論が目的なら、クラウドモデルではなく端末に取得したモデルを選びます。localhostへの接続だけでは推論先を保証できません。

## 2. Yomitomoに接続する

「設定 > モデルとルーティング」でプロバイダーを追加し、OpenAI Chat Completionsプロトコルを選択します。

| 項目 | 設定例 |
| --- | --- |
| 名前 | Ollama local |
| Base URL | `http://localhost:11434/v1` |
| API Key | ローカルサーバー用の仮の値 `ollama` |
| モデル | 取得済みの完全なタグ。例：`qwen2.5:7b` |

モデル一覧を取得するか手動で追加し、接続テスト後に保存します。既定モデルに指定し、タスク別の設定（読書理解 / 詳細レビュー / 二言語翻訳）がリモートモデルを使っていないことも確認してください。

## 3. 原文と照合できる質問を試す

文字を選択できるPDFまたは電子書籍（EPUB・AZW3・MOBI）を取り込み、短い段落を選びます。`A` でハイライトと考えを作成し、対話欄の `@` からアシスタント（`@黒沢 蓮` や `@白川 澪` など）を選択してください。「この結論を支える文章はどこか」などの質問を送り、回答を原文と照合します。

画像のみのスキャンPDFには別途OCRが必要です。最初は機密性のない資料で動作を確認します。基本操作は[リーダー、注釈、ディスカッション](/ja/docs/reader/)を参照してください。

## オフラインで使える範囲

取り込み済みの文書、手動のハイライトや考え、取得済みで互換性のあるローカルモデルは、クラウドモデルAPIなしで利用できます。必要なファイルとモデルを先に取得してから、ネットワークを切った状態で使いたい作業を確認してください。

一方、以下の機能やバックグラウンド処理には通信が発生します。

- Web記事の取得、WeRead同期および内蔵ウェブ版の利用
- 読書メモリー用のローカル埋め込みモデル（`embeddinggemma-300m-ONNX`）を明示的にダウンロードする際の ModelScope / Hugging Face への接続
- アプリ更新確認（`download.yomitomo.app` / `yomitomo.app`）
- 匿名のテレメトリ（`telemetry.yomitomo.app`。既定オン、「設定 > 全般 > プライバシー」でオフ可能。読書内容は送信しません）
- 公開モデル価格表の定期取得（`models.dev`。起動時および24時間ごと。テレメトリ設定とは連動せず、読書内容・APIキー・インストールIDは送信しません）

ローカルAIへの接続は、これらの通信をすべて止めたり、端末を物理的に隔離したりする設定ではありません。詳しくは[設定、モデル、データ管理](/ja/docs/settings/)を参照してください。

## 接続や速度の問題

- 接続拒否：同じ端末でOllamaが起動し、設定したポートで応答するか確認します。
- モデルが見つからない：サイズを含む完全なタグを確認します。
- 遅い・メモリ不足：小さいモデルや短い文脈で試します。
- 通常の応答は成功するがレビューに失敗：モデルと詳細レビュータスクの互換性を確認します。
- リモートへの送信が残る：既定モデルとタスク別ルーティングの割り当てを確認します。

ローカル推論は電力やGPU、メモリを多く使う場合があります。一定の生成速度や低いバッテリー消費を保証するものではありません。
