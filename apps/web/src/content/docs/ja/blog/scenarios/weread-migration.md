WeRead (微信读书) は、中国市場で最もスムーズな電子書籍読書体験の 1 つです。多くの読者がそれに関する数十冊の本を読み、何百ものハイライトや考察を蓄積しています。しかし、遅かれ早かれ、**読書データがプラットフォーム内にロックされている**という壁にぶつかります。

WeRead は公式の全文エクスポートを提供していません。ハイライトを読書メモにまとめたい場合は、メモを 1 つずつ手書きでコピーする必要があります。既存のノートにフォローアップの考えを追加したい場合は、アプリ内でコメントを追加することしかできません。書籍間でのリンクや自由形式の編集はできません。さらに悪いことに、WeRead の使用を中止すると、それらのハイライトや考えはアクセスできないデジタル遺物になってしまいます。

Yomitomoは、WeRead のオープン API を通じて **ローカル移行パス** を提供します。ハイライト、感想、読書の進捗状況を自分のマシンに同期し、ローカルで作業を続けます。

## ステップ 1: API キーを取得して接続する

Yomitomoは WeRead プロキシ サーバーを実行していません。同期は WeRead の公式 API を通じて行われます。必要なのは、WeRead Web クライアントから API キーを取得することだけです。多くのサードパーティの読書統計ツールが機能するのと同様です。

正確な手順は、Yomitomo の「Get a WeRead API Key」ガイドに記載されています。プロセス全体には約 2 分かかります。Web リーダーにログインし、開発者ツールを開き、リクエスト ヘッダーでキー フィールドを見つけて、それをYomitomoの WeRead 設定に貼り付けます。

これは 1 回限りの構成です。セットアップが完了すると、読み取りデータはローカル アプリケーションによって WeRead の API から直接要求されます。サードパーティのサーバーは通過しません。

## ステップ 2: 選択的同期

Yomitomo は、WeRead ライブラリ全体を盲目的に取得することはありません。 WeRead ページでは、同期する書籍を選択し、ハイライト、感想、読書の進捗状況をオンデマンドで取得します。

同期されたコンテンツは、ローカルにインポートされた EPUB、PDF、Web 記事とともに、Yomitomo のライブラリに追加されます。つまり、次のことが可能になります。

- 引き続き WeRead ハイライトに注釈を付けます — Yomitomo の 5 つの注釈タイプ (キー ポイント、前提、概念、質問、引用) は、ローカルのインポートと同様に、同期されたコンテンツに適用されます
- 最初の WeRead の考えの下にフォローアップのコメントや質問を追加します
- AI アシスタントを `@AssistantName` 経由でディスカッションに招待し、WeRead のハイライトやメモに参加してもらいます
- 書籍間の知識を統合するために、蒸留ウィンドウで複数の WeRead 書籍のハイライトを結合します

## ステップ 3: ローカライズ後の自由

データがローカルにあれば、プラットフォームでは提供できない自由が得られます。

- **全文検索**: ライブラリ内のすべての同期された書籍をタイトルのキーワードで検索します
- **書籍間の統合**: 蒸留ウィンドウでは、トピックベースの知識統合のために複数の書籍のハイライトを参照できます。
- **読書統計**: Yomitomoの統計ページには、WeRead データとローカル読書データが組み込まれており、両方のソースからのアクティビティ傾向が表示されます。
- **データ バックアップ**: Yomitomo は SQLite データベースのバックアップと復元をサポートしています - WeRead ノートはローカル ノートと一緒に保護されます

同期は、一度だけ「エクスポートして完了」ではありません。いつでも再同期して、最新の読書の進行状況や新しく追加されたハイライトを取り込むことができます。

## これは誰に向けたものですか

重要なハイライトや考察を蓄積しており、読書データをローカライズし、より深く操作し、プラットフォームのロックインから解放したいと考えている WeRead のヘビー ユーザー。
