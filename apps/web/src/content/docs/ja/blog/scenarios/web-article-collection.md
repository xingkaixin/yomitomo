ナレッジワーカーのブラウザには、例外なく「後で読む記事の墓場」が存在します。Pocket や Instapaper、ブラウザのブックマークに「いつか読む」と自分に言い聞かせながら何百本もの記事を保存し、リストが膨らむにつれて罪悪感とストレスだけが募っていく——。

問題は「後で読む」という行為そのものではなく、従来のツールが**単なる保存をゴールとして設計されていること**にあります。保存ボタンを押した瞬間、脳は「学習を完了した」と錯覚します。しかし後日開いてみても、ただざっと斜め読みしてアーカイブするだけで、分類注釈も対話も蒸留も行われません。これでは読んでも読まなくても認知上の差は生まれません。

Yomitomo は単なるスクラップツールではなく、**クリーンな取り込み → 没入精読 → 多層注釈 → 複数記事の蒸留**という強固なワークフローを提供します。

## ワンクリックでノイズのない精読空間へ

ライブラリで「Web ページを追加」を選び、記事 URL を貼り付けるだけで、広告やサイドバーなどのノイズを排除した純粋な本文と画像が抽出されます。

JavaScript による動的描画（SPA）を多用した記事も、内蔵ブラウザ環境で正しくレンダリングしてから取得します。取り込んだ記事は「未読」「読書中」「読了」のステータスで管理され、能動的なリーディングタスクとして消化できます。

## 流し読みをやめ、原文に思考を刻む

整ったレイアウトで記事を読みながら、テキストを選択して `A` キーを押すだけで即座に注釈を作成できます。

「この推論は鋭い」「この主張には裏付けデータが足りない」といった読書中の直感を、**原文の該当文に紐づいた思考メモ**として確実に残します。疑問が湧いたときは `@水野 花`（問いのメンター）に鋭い問いへと整理させ、`@橘 駿`（洞察エディター）に汎用的なメンタルモデルを抽出させることができます。

## 複数記事の蒸留：断片的な記事を独自のテーマ調査レポートへ

Web 記事は**短く、断片化され、多岐にわたる**という特徴を持ちます。1 本の短い記事の価値は小さくても、同じテーマ（例：「AI エージェントのアーキテクチャ設計」）について読んだ 5 本の記事のハイライトを「蒸留」ウィンドウに集約すれば、強力な個人リサーチノートへと進化します。

2 か月後にチームでその話題が出たとき、バラバラの URL を探し直す必要はありません。あなたの思考と判断が凝縮された蒸留ノートを開くだけです。

## 画像のローカル保存と高速検索

「画像をローカルに保存」を有効にしておけば、Web 記事の挿入画像もすべてローカルディスクに保存されます。元サイトの閉鎖や 404 エラー、オフライン環境に左右されず、いつでも快適に全文を読み返せます。
