すべてのナレッジ ワーカーには「後で読む」墓場があります。 Pocket、Instapaper、ブラウザーのブックマーク、WeChat の「ファイル転送」チャット — あなたは、「いつかこれらにアクセスできるだろう」という希望を抱きながら、何百もの記事を詰め込んできました。時々、リストを開いて不安になり、いくつかの見出しをスワイプして閉じ、さらに見出しを追加し続けることがあります。

問題は「後で読む」という概念そのものではありません。それは、ツールが **保存** をエンドポイントとして扱うことです。記事を保存すると、頭の中に「最終的にはこれを読む」という物語が浮かび上がります。しかし、このツールの設計では「読むか読まないか」、つまり開く→流し読み→アーカイブしかできません。中間処理状態はありません。強調表示もメモも出力もありません。したがって、ほとんどの記事は、「読まれた」後は、認知的には全く読まれなかったことと区別がつきません。記事が何を言ったか、あるいは記事についてどう思ったかを覚えていないのです。

Yomitomoは、別の「後で読む」ツールになることを目指しているわけではありません。 「保存 → スキム」パイプラインを「インポート → 読み取り → ハイライト → 蒸留」にアップグレードします。

## リンクを貼り付けて読み始めてください

Yomitomoのライブラリで、[Web ページを追加] をクリックし、見つけた記事へのリンクを貼り付けます。 Yomitomo はタイトル、著者、本文、画像を抽出し、きれいな読み物アイテムを生成します。

これは、「後で読むために保存する」アクションを置き換えます。違い: 後で読むために保存することは「いつかこれに対処する」ことを意味し、Yomitomoにインポートすることは「今これを読んでいる、または読む予定である」ことを意味します。ライブラリは、読み取りステータス (新規、読み取り中、完了) によるフィルタリングをサポートしているため、インポートは軽量の読み取りトリアージとしても機能します。

ブラウザのレンダリングが必要なページ (JavaScript を多用した動的コンテンツ) の場合、Yomitomo は本文を抽出する前に、組み込みのブラウザを使用してページをレンダリングしようとします。それでも失敗する場合は、積極的なボット保護を備えた少数のサイトが正常にインポートされない可能性があります。

## 読みながらマークを付ける — 流し読みするだけではない

インポートされた Web 記事を開くと、EPUB や PDF と同じリーダーが入力されます。すっきりとしたタイポグラフィ、本文は中央揃え、サイドバーや推奨フィードはありません。テキストを選択し、`A` を押し、注釈の種類を選択し、反応を書き込みます。

このステップは、ウェブ記事を「灰色」から「生きた」ものに変えるものです。流し読みをしていたとき、脳の反応は「ふーん、なるほど」、「興味深いデータポイント」、「私はそう思わない」といったものでしたが、その後、それらの反応は消えていきました。これからは、それらを元の段落に固定された**文書記録**に変換します。

「質問」としてマークされた文章を AI アシスタントに投げることもできます。 `@Xu Wenqu` は漠然とした混乱を正確な質問に変えます。 `@Chen Yanshu` は、特定のケースから転送可能な洞察を抽出します。議論はハイライトの横にあり、読書の足跡の一部になります。

## 単独の記事から複数の記事の統合へ

ウェブ記事は、**短く、散在しており、数が多い**という特徴があります。 3,000 ワードの長文、800 ワードの業界速報、ブログの技術分析など、ソースは異なりますが、多くの場合、同じテーマに収束します。

Yomitomoの蒸留ウィンドウでは、複数の記事のハイライトを集約できます。最近、「AI コーディング ツール」に関する記事を 5 冊読んだとしましょう。それぞれにいくつかのハイライトが含まれています。 [蒸留] ウィンドウで、これらの 5 つの記事を選択し、散らばった考えを構造化されたメモに統合します。つまり、どのツールを比較したか、どの側面に関心があるか、どのような判断を下したかなどです。

読まれてアーカイブされた単一のウェブ記事の価値は限られています。しかし、同じトピックに関する 5 つの記事を 1 つの抽出物に統合すると、**再利用可能な個人研究**になります。 2 か月後、誰かが「これらの AI コーディング ツールについてどう思いますか」と尋ねたとき、5 つの記事を再検索する必要はありません。抽出結果を開くと、すぐに判断が得られます。

## 歴史的な記事を失わないでください

Yomitomoは「画像をローカルに保存」を有効にすることができます。有効にすると、Web 記事をインポートすると、本文の画像もマシンに保存されます。つまり、元のサイトのデザインが変更されたり、記事が削除されたり、オフラインになったりしても、記事を全文読むことができます。

ライブラリでは、タイトルと著者のキーワードによる検索をサポートしています。 「React Server Components に関する記事を読んだ」ということを漠然と覚えている場合は、キーワード検索でそれが見つかります。 「読んだはずなのに二度と見つからない」というイライラはもうありません。

## これは誰に向けたものですか

毎日、読む価値のあるウェブ記事にたくさん遭遇しながらも、実際に読んでいる記事は 20% 未満であるナレッジ ワーカー。保存→忘れ→再度保存というサイクルに飽きていて、断片的な読書を蓄積された知識資産に変換したい場合。
