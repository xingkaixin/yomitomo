現在、多くの読書・ノートアプリがクラウド保存を前提にしています。複数端末からすぐ開ける便利さがある一方、**読書中の思考データが手元に残らない**というコストも伴います。

読書中のハイライト、疑問、未整理の考えは、公開されたメモとは性質が異なります。外部クラウドにすべて預ける設計では、規約変更、価格改定、サービス終了の影響を常に受け続けます。

Yomitomoは異なる方針を選んでいます。それが**ローカルファースト（Local-First）**です。アカウント登録なしで、取り込んだ資料・ハイライト・自分の考え・対話・まとめ（蒸留）を端末内のSQLiteとファイル領域に保存します。

---

## ローカル保存のアーキテクチャと境界

| コンポーネント | 入力と操作 | システム内部処理 | 保存と成果物 | 境界と注意点 |
|---|---|---|---|---|
| **ライブラリ** | Web記事、電子書籍（EPUB・AZW3・MOBI）、PDF、テキスト・Markdown（`.txt`/`.md`）、WeRead同期ノート | ローカルで解析し、ファイル領域とSQLiteへ保存 | ローカルSQLiteと元文書ファイル | Yomitomo側に読書内容を保管するクラウドDBはありません |
| **注釈・対話・まとめ** | ハイライト（`A` またはワンクリック）、考え、ディスカッション、まとめ（蒸留） | 原文アンカーの紐付け、ローカルSQLiteへの永続化、キーワード検索 | 原文に結び付いた注釈履歴と公開済み「まとめ」 | AIや通信がなくても閲覧・記録・検索が動作します |
| **読書メモリー** | ローカル資料の保存済みハイライト・考え・参加した議論・公開済みまとめ | ローカルSQLite＋任意のローカル埋め込みモデル（`embeddinggemma-300m-ONNX`）で検索 | 「まとめ」一覧、「ライブラリに質問」、「読み直す」、「関連を探す」 | 対象はローカル資料のみ（WeRead書籍・全文・未公開下書きは対象外）。埋め込み処理は端末内で完結します |
| **認証情報とバックアップ** | APIキー（OpenAI / Anthropic / DeepSeek / Ollama等）、WeRead APIキー | OS標準の資格情報ストア（macOS Keychain / Windows 資格情報マネージャー）で暗号化管理 | 完全バックアップまたはデータベースのみのバックアップ | 完全バックアップはDB・元文書・PDFサムネイルを含み、APIキー・アプリロック・WeRead内蔵ウェブ版のログイン状態は含みません |

## 端末外へ発生する通信の範囲

ローカルファーストであっても、機能に応じて端末外との通信は発生します。Yomitomoが外部と通信する経路は以下の7種類に限られます。

1. **AI・翻訳プロバイダー**：チャット、まとめの整理・レビュー、二言語翻訳、「ライブラリに質問」を実行したとき、その処理に必要な原文・対話・指示文を設定したプロバイダーへ直接送信します（Yomitomoの中継サーバーはありません）。端末内のOllama等を指定すれば推論はローカルで完結します。
2. **Web記事の取り込み先URL**：URLから記事を取り込む際、対象のWebページ（およびローカル保存用の画像）へ直接アクセスします。
3. **WeRead（微信読書）**：公式 Skill API での同期時、および「設定 > データソース > WeRead」から内蔵ウェブ版を開いたときに WeRead 側へ通信します。
4. **読書メモリー用モデルのダウンロード**：ローカル埋め込みモデル（`embeddinggemma-300m-ONNX`）をユーザーが明示的にダウンロードするとき、ModelScope または Hugging Face から取得します。
5. **アプリの更新確認**：アップデート確認のために `download.yomitomo.app` および `yomitomo.app` へアクセスします。
6. **匿名テレメトリ（`telemetry.yomitomo.app`）**：既定でオンになっており、「設定 > 全般 > プライバシー」でオフにできます。送信するのは日次の匿名ハートビートと、インストールIDを含まない読書メモリーの操作回数のみで、読書内容やファイル名は送信しません。
7. **公開モデル価格表（`models.dev`）**：起動時および24時間ごとに `models.dev` から公開モデル価格表をGET取得します（「統計 > アシスタント使用量」の推定コスト計算に使用）。テレメトリ設定とは連動せず、読書内容・APIキー・インストールIDは送信しません。

## ローカルファーストがもたらす4つの利点

### 1. アカウント不要で手元にデータが残る
すべての読書記録は自分のPC内に保存されます。アカウント登録やログインは不要で、クラウド側のサービス終了や規約変更によってデータへアクセスできなくなる心配がありません。

### 2. OS標準の資格情報ストアによる鍵管理
APIキーは平文の設定ファイルには置きません。macOS KeychainやWindows 資格情報マネージャーで保護し、データベースファイルをコピーしてもキーは含まれない設計です。

### 3. AIやネットワークがなくても読書が止まらない
取り込み済みの文書に対する閲覧、ハイライト、自分の考えの保存、キーワード検索、まとめの編集はネットワークなしでも動作します。事前に取得したローカルモデル（Ollama等）を割り当てれば、クラウドモデルAPIを使わずにAI対話も行えます。

### 4. SQLiteとMarkdown出力による持ち出しやすさ
注釈・対話・まとめの本文は標準的なSQLiteファイルに保存され、元ファイルとは分離されています。また、リーダーやまとめ画面から「Markdown (.md) をエクスポート」「Markdownをコピー」でいつでもプレーンテキストとして取り出せます。

## 対象読者と利用の境界

### こんな方におすすめ

- 研究資料、レポート、専門書を扱い、データ主権とプライバシー境界を明確にしたい知識労働者
- SaaSの継続課金やクラウド囲い込みを避け、手元にアーカイブを残したい読者
- 移動中やオフライン環境でも安定して精読・メモを続けたい方
- 自前のAPIキーや端末内のOllamaモデルを使い分けたい方

### 適していないケース

- **複数人でのリアルタイム同時編集**：個人の精読と思考整理に特化しています
- **クラウドでの常時マルチデバイス同期**：端末間移行はバックアップと復元で行います

## よくある質問 (FAQ)

### Q1: 複数台のPC間でデータを移行するにはどうすればよいですか？
**回答:** 「設定 > データ管理」で完全バックアップを作成し、フォルダー全体を別の端末へコピーして復元します。完全バックアップにはデータベース、元の電子書籍・PDF、PDFサムネイルが含まれます。APIキー、アプリロック、WeRead内蔵ウェブ版のログイン状態は移行されないため、復元後に再設定してください。詳しくは[設定、モデル、データ管理](/ja/docs/settings/#データ管理とバックアップ)をご覧ください。

### Q2: 登録したAPIキーがYomitomoの開発者へ送信されることはありますか？
**回答:** ありません。YomitomoはLLMリクエストを中継せず、APIキーはOSの資格情報ストアに保存されます。リクエストは設定したモデルプロバイダーへ直接送信されるため、リモートプロバイダーを使う場合はその接続先が認証キーと処理対象のテキストを受信します。

### Q3: Yomitomoの更新が止まった場合、過去のノートはどうなりますか？
**回答:** ローカルの標準的なSQLiteデータベースに保存されているほか、Markdown (.md) でのエクスポートにも対応しているため、一般的なツールやスクリプトで全データを取り出せます。
