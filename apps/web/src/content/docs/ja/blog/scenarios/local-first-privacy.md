2026 年までに、「クラウド ファースト」がソフトウェア開発のデフォルトになります。クラウド上のメモ、クラウド上のドキュメント、クラウド上のデータの読み取り。このモデルは、クロスデバイス同期の利便性をもたらしますが、広く受け入れられているものの、あまり議論されていない代償も伴います。**あなたの読書データはあなたのものではなくなります**。

読み取りデータは他のデータとは異なります。それはカレンダーのイベントやタスクリストではなく、あなたと世界との交流の記録です。データを読むことは、**思考プロセス**です。一節の横にある欄外メモ、主張に対する疑問、ある概念から別の概念へと心がたどった道な​​どです。このデータはあなたの認知の軌跡を構成します。データをクラウドに渡すということは、サービス プロバイダーがデータを分析したり、その上でモデルをトレーニングしたり、サービスのシャットダウン時に消去したりできることを暗黙のうちに受け入れたことを意味します。

Yomitomoは別の道、**ローカルファースト**を選択しました。

## コンピュータに保存されているすべてのデータ

Yomitomoのすべての読書データ (インポートされた記事、EPUB、PDF、ハイライト、注釈、ディスカッション、蒸留、読書統計) はすべて、デスクトップ アプリケーション データ ディレクトリに保存されます。 Yomitomo のクラウド サーバーに読書コンテンツが保存されることはありません。

これは次のことを意味します:

- アカウントを作成する必要はありません。ダウンロードしてインストールし、使用を開始してください。
- あなたの読書データは、サービス プロバイダーのポリシー変更の影響を受けません。
- すべての機能を完全にオフラインで使用できます (モデル API を呼び出すためにインターネットが必要な AI アシスタントを除く)。
- 誰もあなたの読書の好みや思考パターンを分析することはできません。

## システム キーリングに保存される API キー

Yomitomoは、アシスタント機能のために AI モデル プロバイダー (OpenAI、Anthropic、DeepSeek など) に接続する必要があります。ただし、API キーはYomitomoの通常の設定ファイルには保存されません。

Yomitomoは、オペレーティング システムのキーリング (macOS キーチェーン、Windows Credential Manager) を使用して API キーを保存します。 SQLite データベースはプロバイダー構成とキー参照のみを保持し、プレーンテキストのキーは保持しません。つまり、誰かがあなたのYomitomoデータ ファイルにアクセスしたとしても、API キーを読み取ることはできません。

API 呼び出しは、ローカル アプリケーションからモデル プロバイダーのサーバーに直接送信されます。 Yomitomo は、これらのリクエストを代理したり転送したりすることはありません。 API キーは、あなたとモデルプロバイダーのみが知っています。

## オフラインでも完全に機能

Yomitomoの中核となる読書機能、記事のインポート、EPUB や PDF の読み取り、ハイライト表示、注釈付け、ディスカッション、抽出などはすべて完全にオフラインで動作します。完全な深読みセッションを完了するには、インターネット接続は必要ありません。

AI アシスタント機能には接続が必要ですが (モデル推論はクラウドで実行されるため)、オプションです。すべての AI アシスタントを無効にして、純粋にオフラインの読書および注釈ツールとして Yomitomo を使用することができます。

この設計は、「クラウド ファースト」ツールとははっきりと対照的です。クラウド ツールは、ネットワークが切断されると機能が低下したり使用できなくなったりしますが、ローカル ファースト ツールは、オフライン時に**コア機能を失う**のではなく、オンライン時に**追加機能を獲得**します。

## データのバックアップとポータビリティ

ローカルファーストはデータの脆弱性を意味するものではありません。 Yomitomo は、SQLite データベースのバックアップおよび復元機能を提供します。データベース ファイルを定期的にエクスポートし、信頼できる外部ドライブまたはクラウド ストレージ サービスにバックアップできます。

データベース形式は標準の SQLite です。これは、たとえいつかYomitomoの使用をやめたとしても、データは独自の形式でロックされないことを意味します。任意の SQLite ツールを使用して、読み取りデータを開いたり、クエリを実行したり、エクスポートしたりできます。

WeRead の同期データはローカルの SQLite データベースにも保存されます。 WeRead のハイライトと考えがローカルに同期されると、WeRead プラットフォームから完全に独立します。

## 読書のプライバシー

読書は基本的に私的な行為です。本の中でマークを付けた箇所、書き留めた質問、これらはあなたが取り組んでいる問題、直面している混乱、さらにはあなた自身との内面の対話である可能性があります。このコンテンツは、どのクラウド サービスの分析ダッシュボードにも属しません。

ローカルファーストは、読書中に自分の無知や混乱を安全にさらけ出せることを保証します。そしてそれはまさにディープラーニングの前提条件です。すべてのアノテーションが分析されたり、モデルのトレーニングに使用されたり、いつか漏洩される可能性があると知っていたら、無意識のうちに自己検閲して、弱点を明らかにしない「安全な」メモを書くでしょう。そして、それらの「安全なメモ」には認知的価値はゼロです。

## これは誰に向けたものですか

データのプライバシーに敏感な人、オフライン環境で頻繁に読書をする人、または単純に「自分の考えは自分のハードドライブに保存すべきだ」と信じている人。 「すべてをクラウドに」というトレンドに不安を感じる場合は、ローカルファーストが最も根本的な解決策です。
