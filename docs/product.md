# Yomitomo 产品方向

本文记录产品定位、目标、非目标和取舍原则。新需求与本文冲突时，先修改本文并写明理由，再改代码。
领域术语见根目录 `CONTEXT.md`，模块边界见 [架构概览](architecture.md)。

## 定位

Yomitomo 是本地优先的 AI 伴读桌面应用。用户把网页文章、EPUB/AZW3/MOBI、PDF、文本和微信读书
笔记放进同一个阅读库，在原文上划线、写想法，并和自己配置的 AI 阅读助手讨论。

核心承诺是在阅读现场增加理解、共鸣和反思，不替用户读完。

## 目标

- **多来源阅读**：Web、EPUB、PDF 和文本共用一个阅读库和一套批注模型。微信读书书籍作为远端同步
  条目与本地 Article 并列，身份保持区分。
- **锚定在原文上的讨论**：批注锚定原文位置。想法、回复、@助手讨论和沉淀都围绕锚点展开，
  重新打开后能恢复高亮和定位。
- **克制、可控的 AI 伴读**：用户选择助手、provider 和触发时机。AI 输出必须锚定原文并通过筛选。
- **可回看的阅读资产**：已保存的划线、想法和已发布的沉淀可以被检索、关联和重新审视，
  AI 给出的主张能跳回原文证据。
- **用户拥有数据**：数据保存在本机，可完整备份和还原；用户自带 LLM provider。

## 非目标

- 不做账号体系、跨设备云同步、团队协作或云端人格记忆。微信读书同步使用用户自己的 API key
  调用微信读书服务，不经过 Yomitomo 服务端。
- 不把"读后笔记""读后总结""读后产出物"作为主路径。沉淀是对单条批注讨论的整理和发布，
  不是全文总结。
- 不提供或代理 LLM 服务。所有 AI 调用都发往用户配置的 provider。
- 不依赖外部向量数据库，不做模型微调。阅读记忆使用本地 embedding 模型和 SQLite。
- 不收集阅读内容。匿名遥测的范围见下方隐私边界。

## 取舍原则

1. **注意力是最稀缺的资源。** 主动的 AI 输出都在消耗注意力，必须先证明值得打断再进入界面。
   宁可少说，不要抢先。
2. **屏幕位置不等于已读。** 滚动到某处或翻到某页，不作为自动生成或展开 AI 批注的触发条件。
   主动生成只由用户的显式动作启动，例如共读或 @助手。
3. **不改写用户的原文。** 划线归属用户。用户写下的想法原样保存和展示；可以为路由和 prompt
   提取意图，但不改动持久化内容。
4. **不直接相信模型自评。** 候选批注必须落在请求范围内并能锚定原文，再经过确定性筛选
   （锚点、重复、密度、`shouldShow`）。不满足就丢弃，不降级成无锚点内容。
5. **区分助手想法和助手评论。** 助手想法是助手创建的锚定批注；助手评论是对用户想法或讨论的
   回复，由用户发起。
6. **引用必须可回溯。** 阅读记忆、问书库和重新审视中的 AI 主张只能引用有效的原始资产，
   并能跳回原文。引用合法不等于内容支持主张，后者需要人工验收。
7. **AI 不可用时降级，不阻断阅读。** 普通阅读和手动批注不需要配置 AI。没有模型、没有 provider
   或远程失败时，阅读、批注和关键词检索仍可用；保存不等待 AI、向量或远程调用。
8. **新增外发数据先改本文。** 任何会让新的数据离开本机的功能，先更新下方隐私边界和对外说明。

## 隐私边界

阅读内容、书名、批注、评论、文件路径、AI 对话保存在本机 SQLite 和应用数据目录中。
provider API key 保存在系统 keyring，数据库只存引用；完整备份不包含 API key。

只有以下情况会有数据离开本机：

| 去向 | 触发条件 | 内容 |
| --- | --- | --- |
| 用户配置的 LLM provider | 用户触发 AI 功能 | 完成该任务所需的选中文本、上下文、批注或评论 |
| 网页导入的目标站点 | 用户导入 URL | 普通页面请求 |
| 微信读书 | 用户配置 API key 后同步 | 微信读书 API 请求 |
| ModelScope / Hugging Face | 用户明确下载阅读记忆模型 | 固定版本模型文件请求，不含阅读内容 |
| `download.yomitomo.app`、`yomitomo.app` | 检查与下载更新 | 更新 manifest、安装包与更新说明请求 |
| `telemetry.yomitomo.app` | 默认开启，可在设置中关闭 | 每天最多一次匿名 heartbeat（安装标识、版本、平台与系统信息）；阅读记忆动作计数，不含安装标识 |
